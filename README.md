# Bank AI Firewall

Банк, к которому AI-агенту дали доступ, упирается в один вопрос: что помешает
агенту списать деньги не туда. Ответ «не давать доступ» работает, но тогда и
пользы нет. Здесь ответ другой — **владелец описывает, что агенту можно, до
копейки**, а всё остальное либо не проходит, либо приходит к нему на подтверждение.

```
    AI-агент ──▶ MCP Т-Банка ──▶ 🔥 ФАЕРВОЛ ──▶ банк
                                    │
                                    ▼
                            вебморда владельца:
                    правила · лимиты · списки · подтверждения · журнал
```

## Что умеет

- **Правила** — как ACL: список сверху вниз, первое совпавшее решает. Разрешить,
  запретить или спросить человека.
- **Разрезы** — тул, тип операции (чтение/запись/деньги), категория расхода, сумма,
  получатель, организация, счёт списания, карта, свободный текст.
- **Условия** — сравнения по сумме, точное совпадение, подстрока, префикс,
  регулярка, перечень, вхождение в список.
- **Белые и чёрные списки** получателей, организаций, карт и стоп-слов.
- **Лимиты** по сумме и по количеству операций: на одну операцию, в час, в сутки,
  в неделю, в месяц. Окна календарные; отклонённые операции потолок не расходуют.
- **Норма без подтверждения** — у каждого разрешающего правила своя квота: «до
  3 000 ₽ три раза в сутки по этим категориям агент тратит молча, дальше операция
  идёт на подтверждение». Израсходованное видно прямо в списке правил.
- **Подтверждение человеком (HITL)** — два сценария: агент получает ссылку и
  отпускает вызов, либо вызов ждёт решения. Подтверждение одноразовое и действует
  ровно на ту операцию, которую показали.
- **Защита от выдуманных реквизитов** — идентификаторы банка получателя в СБП
  нельзя вывести из номера телефона, их отдаёт только резолв. Если агент подставил
  их сам, перевод не уйдёт: фаервол помнит, что банк действительно возвращал.
- **Зона видимости** — какие туллы агент видит, какие видит но не может позвать,
  каких не видит вовсе; плюс маски на ответах (номер карты и CVV не попадают в
  контекст модели, даже если вызов разрешён).
- **Журнал** — каждый вызов: аргументы, сработавшее правило, решение, исход.
  Пароли, PIN, коды из SMS и платёжные токены не сохраняются.

## Быстрый старт

```bash
cp .env.example .env                # укажите, где хранить сессию банка
docker compose up -d --build        # вебморда :8080, демон входа :8765
```

Обе службы поднимаются с `restart: unless-stopped`, состояние лежит в томах —
перезагрузка сервера переживается без ручных действий (если сам Docker стартует
при загрузке).

Дальше — подключить агента. Claude Desktop и Claude Code запускают MCP по stdio
как дочерний процесс, поэтому он живёт на хосте и читает ту же сессию:

```bash
cd mcp
python3.11 -m venv .venv && .venv/bin/pip install -e .
claude mcp add tbank -- "$PWD/.venv/bin/python" -m src.server
```

Клиентам, умеющим HTTP-транспорт, MCP можно поднять тоже в Docker:
`docker compose --profile mcp-http up -d` — сервер появится на `127.0.0.1:8000`.

Войти — на вкладке **«Вход»**: телефон, код из SMS, пароль. Форму рисует вебморда,
но введённое уходит **напрямую в демон на вашей машине**, минуя фаервол: пароль не
проходит через контейнер, не пишется в журнал и не попадает в контекст модели.
Сессия ложится в `~/.local/share/tbank-mcp/session.json` (0600) — оттуда её и читает
MCP. Кому привычнее терминал, остался `login_cli.py +7XXXXXXXXXX`.

Откройте `http://127.0.0.1:8080` — там уже заведена стартовая политика: чтение
разрешено, деньги идут на подтверждение, потолок одной операции 15 000 ₽,
суточный 30 000 ₽, стоп-слова про крипту и ставки запрещены.

Проверить правило, ничего не потратив, можно прямо на странице «Правила» — там
есть симулятор: он прогоняет придуманный вызов через политику и показывает
решение, не записывая ничего в журнал.

## Как это выглядит для агента

```
> Переведи 1500 рублей на +7 999 123-45-67

⏳ НУЖНО ПОДТВЕРЖДЕНИЕ ВЛАДЕЛЬЦА
Операция: Перевод денег (transfer) · 1500.00 ₽ · → +79991234567
Причина: операция списывает деньги
Подтвердить или отклонить: http://127.0.0.1:8080/hitl/req_000fe399213a
```

Владелец открывает ссылку, видит сумму и получателя, нажимает «Подтвердить» —
агент повторяет тот же вызов, и он проходит. Один раз: другая сумма или другой
получатель спросят заново.

## Claude Desktop: отдельный «Финансовый помощник»

Чтобы финансовый системный промпт не лез в обычные чаты, а деньги двигались
только там, где вы этого ждёте — [пошаговая инструкция](docs/claude-desktop.md):
проект с собственными инструкциями, два подключения MCP и правило фаервола,
которое это подпирает. Готовый текст промпта — в
[`docs/project-instructions.md`](docs/project-instructions.md).

Подагентов в Claude Desktop нет — это фича Claude Code. Инструкция объясняет,
чем именно закрывается каждая часть задачи и что из этого настоящая граница, а
что дисциплина.

## Состав

- `firewall/` — веб-приложение и движок правил (FastAPI + SQLite, без ORM и без
  фронтенд-сборки). Всё состояние — один файл в volume.
- `mcp/` — форк [icyberdeveloper/tbank-mcp](https://github.com/icyberdeveloper/tbank-mcp):
  61 тул к API банка плюс врезка фаервола в `src/guard.py`.
- `docs/` — настройка Claude Desktop и готовые инструкции проекта.
- `CLAUDE.md` — как это устроено внутри и что легко сломать.

## Безопасность

Вебморда **пока без аутентификации**, поэтому compose биндит её на `127.0.0.1` —
никуда, кроме этой машины, она не доступна. Не выставляйте её наружу до того, как
появится вход: это панель, которая подтверждает переводы одной кнопкой.

При недоступном фаерволе MCP по умолчанию **отказывает** во всём. Это неудобно и
это намеренно: «фаервол упал» не может означать «значит, можно всё».

Не для продакшена банка. Личный инструмент для собственного счёта.
